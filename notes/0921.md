# 2026-09-21：最小の起動、UART 出力、例外処理

RISC-V と C++ で、QEMU 上で動く小さな OS を作る。まず起動と文字出力を確認し、例外の原因と場所を調べられるところまで進めた。

コードは学習した段階ごとの抜粋。翌日に追加した `.bss` のゼロ化とネットワーク機器の操作は [0922.md](0922.md) にまとめる。

## 1. 起動から C++ まで

```text
QEMU が kernel.elf を読み込む
    ↓
自分たちの _start に入る
    ↓
sp に stack_top を設定する
    ↓
kernel_main を呼ぶ
```

`sp` はスタックの位置を保持するレジスタ。スタックは、関数の戻り先や一時的な値などを保存するために使う。

```asm
.section .bss
.balign 16
stack_bottom:
    .space 4096
stack_top:
```

- `.space 4096` で 4 KiB の領域を確保する。
- スタックは高いアドレスから低いアドレスへ伸びるので、最初は末尾の `stack_top` を `sp` に入れる。
- `.balign 16` は先頭を16バイト境界にそろえる指定。4096も16の倍数なので末尾もそろい、C++ の関数を呼ぶ際の約束を満たせる。

```cpp
extern "C" void kernel_main() {
    for (;;) {
    }
}
```

`extern "C"` は、C++ による関数名の変換を避け、アセンブリから `kernel_main` という名前で呼べるようにする指定。無限ループで関数から戻らないようにしている。

## 2. リンカスクリプトで配置を決める

リンカは、`boot.o` と `kernel.o` などの部品を結合して実行ファイルを作るツール。`linker.ld` は配置の指示書。

```ld
ENTRY(_start)

SECTIONS
{
    . = 0x80000000;

    .text : {
        boot.o(.text)
        *(.text .text.*)
    }

    .rodata : {
        *(.rodata .rodata.*)
    }

    .data : {
        *(.data .data.*)
        *(.sdata .sdata.*)
    }

    .bss : {
        *(.bss .bss.*)
        *(.sbss .sbss.*)
    }
}
```

セクションは、用途ごとにまとめた領域のこと。

| 名前・指定 | 意味 |
|---|---|
| `ENTRY(_start)` | 実行開始位置を `_start` にする |
| `.` | リンカが現在配置している位置 |
| `.text` | 実行する命令 |
| `.rodata` | 文字列などの読み取り専用データ |
| `.data` | ゼロ以外の初期値を持つ変数など |
| `.bss` | ゼロ初期化する変数や、今回のスタック領域 |

`boot.o(.text)` は、`boot.o` の命令を出力の `.text` の先頭に置く指定。`*(.text .text.*)` は、入力ファイルから該当する名前のセクションを集める指定。ここでの `*` は名前の一致に使うもので、C++ のポインタ演算ではない。

QEMU の `virt` では RAM が `0x80000000` から始まるので、今回はそこから配置する。すべての RISC-V 実機で共通するアドレスではない。

元のメモの `.rodat` は誤字。コンパイラが使う名前に合わせて `.rodata` と書く。`.sdata` と `.sbss` は小さなデータ用の領域で、今はそれぞれ `.data` と `.bss` にまとめればよい。

## 3. コンパイルとリンク

アセンブリと C++ を、それぞれ機械語の部品であるオブジェクトファイルに変換する。

```sh
clang++ --target=riscv64-unknown-elf \
  -march=rv64imac -mabi=lp64 \
  -c boot.S -o boot.o

clang++ --target=riscv64-unknown-elf \
  -march=rv64imac -mabi=lp64 \
  -ffreestanding -fno-exceptions -fno-rtti \
  -mcmodel=medany \
  -c kernel.cpp -o kernel.o

ld.lld -T linker.ld boot.o kernel.o -o kernel.elf
```

| オプション | 目的 |
|---|---|
| `--target=riscv64-unknown-elf` | RISC-V 64ビット向けに生成する |
| `-march=rv64imac` | 使用する命令セットを選ぶ |
| `-mabi=lp64` | 関数呼び出しや型のサイズの約束を選ぶ。今回の `int` は32ビット、`long` とポインタは64ビット |
| `-ffreestanding` | OS が提供する通常の実行環境を前提にしない |
| `-fno-exceptions` | C++ の例外処理を無効にする |
| `-fno-rtti` | C++ の実行時の型情報を無効にする |
| `-mcmodel=medany` | 今回の配置に対応するアドレス参照方式を使う |
| `-c` | コンパイルだけ行い、まだリンクしない |
| `-T linker.ld` | リンク時に配置の指示書を使う |
| `-o` | 出力ファイル名を指定する |

ELF は、機械語に加えて配置先や実行開始アドレスなどを記録する形式。

```sh
readelf -h kernel.elf
```

`Machine: RISC-V`、`Entry point address: 0x80000000` を確認した。後で CSR を使う段階では、上の2つのコンパイルコマンドの `-march` に `_zicsr` を追加した。

## 4. QEMU で起動する

QEMU は CPU や周辺機器をソフトウェアで再現するツール。

```sh
qemu-system-riscv64 \
  -machine virt \
  -bios none \
  -smp 1 \
  -m 128M \
  -nographic \
  -kernel kernel.elf
```

| オプション | 意味 |
|---|---|
| `-machine virt` | 仮想ボード `virt` を使う |
| `-bios none` | 既存の起動ファームウェアを使わない |
| `-smp 1` | CPU を1つにする |
| `-m 128M` | RAM を128 MiB にする |
| `-nographic` | 別ウィンドウを開かず、シリアル入出力などにターミナルを使う |
| `-kernel kernel.elf` | 作成した ELF を読み込む |

終了は **Ctrl+A を押して離し、その後 X**。

文字出力がない段階では何も表示されず動き続ける。ただし、それだけでは `kernel_main` に到達した証明にはならない。

## 5. UART と MMIO：まず1文字を出す

UART は、文字などをシリアル通信で送受信する装置。MMIO は、特定のアドレスへの読み書きで機器を操作する仕組み。

```cpp
extern "C" void kernel_main() {
    volatile unsigned char* uart =
        reinterpret_cast<volatile unsigned char*>(0x10000000);

    *uart = 'A';
    for (;;) {
    }
}
```

- `reinterpret_cast`：数値を、機器にアクセスするためのポインタとして扱う。
- `volatile`：この読み書きをコンパイラが不要と判断して削除することなどを防ぐ。あらゆるメモリの順序を保証する指定ではない。
- `unsigned char*`：この UART の送信レジスタへ1バイト単位で書くため。
- `*uart = 'A'`：RAM に文字を保存するのではなく、機器へ送信を指示する。

ターミナルに出る流れ：

```text
自作 OS が UART に書く
    ↓
QEMU が仮想 UART の書き込みを処理する
    ↓
-nographic の設定に従い、ターミナルに文字を出す
```

自作 OS はホスト側のターミナルを直接操作していない。実機では、UART の信号を別の PC で受信して表示する構成などになる。

## 6. 送信待ちと文字列出力

```cpp
void uart_putc(char c) {
    volatile unsigned char* uart =
        reinterpret_cast<volatile unsigned char*>(0x10000000);

    // Wait until ready.
    while ((uart[5] & 0x20) == 0) {
    }

    uart[0] = c;
}

void uart_puts(const char* text) {
    while (*text != '\0') {
        uart_putc(*text);
        ++text;
    }
}
```

`uart` は普通の配列を確保したものではなく、機器のアドレスを指すポインタ。ポインタにも `[]` が使える。

| 式 | アドレス | 用途 |
|---|---|---|
| `uart[0]` | `0x10000000` | 1バイト送信する |
| `uart[5]` | `0x10000005` | UART の状態を読む |

`uart[5] & 0x20` は、「送信用の保持レジスタが空か」を示すビットを取り出す。ゼロなら待ち、ゼロでなければ次の文字を書く。状態を繰り返し読む方法を **ポーリング**と呼ぶ。

`uart_putc` は1バイト送信、`uart_puts` は文字列送信として名前を分けた。元のメモの `uart_puts(char c)` は、改名前の1文字送信関数。

文字列は終端の `\0` まで1バイトずつ送る。`const` は、このポインタ経由で文字を書き換えないという指定。英数字は通常1文字1バイトだが、UTF-8 の日本語は1文字が複数バイトになる。

```cpp
uart_puts("Hello!\r\n");
```

`\r` は行頭に戻し、`\n` は次の行へ進める。文字列リテラルの末尾にはコンパイラが `\0` を付ける。

## 7. Makefile でコマンドをまとめる

基本形は「作りたいもの：必要なファイル」と、その下の作り方。

```makefile
kernel.elf: boot.o kernel.o linker.ld
	ld.lld -T linker.ld boot.o kernel.o -o kernel.elf

boot.o: boot.S
	clang++ --target=riscv64-unknown-elf -march=rv64imac_zicsr -mabi=lp64 -c boot.S -o boot.o

kernel.o: kernel.cpp
	clang++ --target=riscv64-unknown-elf -march=rv64imac_zicsr -mabi=lp64 -ffreestanding -fno-exceptions -fno-rtti -mcmodel=medany -c kernel.cpp -o kernel.o

.PHONY: run
run: kernel.elf
	qemu-system-riscv64 -machine virt -bios none -smp 1 -m 128M -nographic -kernel kernel.elf
```

コマンド行の先頭にはスペースではなく **Tab** が必要。

- `make`：最初のターゲット `kernel.elf` を、必要な部分だけ作り直す。
- `make -B`：更新時刻に関係なく作り直す。コンパイルオプションを変えたときにも使った。
- `make run`：必要ならビルドし、その後 QEMU を起動する。
- `run: kernel.elf`：起動前に `kernel.elf` を用意するという依存関係。
- `.PHONY: run`：`run` は生成ファイルではなく操作名だと伝える。`run` というファイルがあっても起動コマンドを実行できる。

`.PHONY` 自体が「ELF がある場合に run を作る」という意味ではない。

## 8. トラップの入口を登録する

**トラップ**は、CPU が例外や割り込みを受けて専用の処理へ移ること。今回は意図的な例外を使い、表示して停止するだけにした。C++ の `throw` / `catch` とは別の仕組み。

CSR は CPU の状態や制御に使う特殊なレジスタ。アクセス命令を使うため、ビルド設定を `-march=rv64imac_zicsr` に変更した。

| 指定 | 意味 |
|---|---|
| `rv64` | 64ビット RISC-V |
| `i` | 基本整数命令 |
| `m` | 乗算・除算 |
| `a` | 他の実行主体から見て不可分なメモリ操作などを行うアトミック命令 |
| `c` | 一部の命令を16ビットで表現する圧縮命令 |
| `zicsr` | CSR の読み書き命令 |

アトミック命令は、共有メモリを複数の CPU などで扱うときに役立つ。圧縮命令はすべての命令を16ビット化するものではなく、コードサイズを小さくできるもの。詳しい使い方は今は後回し。

| CSR | 役割 |
|---|---|
| `mtvec` | トラップ処理の入口 |
| `mcause` | トラップの原因 |
| `mepc` | 例外を起こした命令、または割り込まれた命令のアドレス |
| `mstatus` | CPU の制御状態。今回は直接操作しない |

```asm
_start:
    la sp, stack_top

    # Set the trap entry.
    la t0, trap_entry
    csrw mtvec, t0

    call kernel_main

halt:
    j halt

.balign 4
trap_entry:
    call trap_handler
    j halt
```

- `la t0, trap_entry`：入口のアドレスを一時レジスタ `t0` に入れる。
- `csrw mtvec, t0`：そのアドレスを CPU に登録する。
- `.balign 4`：入口を4バイト境界にそろえる。今回使う `mtvec` の直接方式の要件。
- 例外が起きると CPU が `trap_entry` に飛び、そこから C++ の `trap_handler` を呼ぶ。

カーネルの各処理に例外チェックを書くのではなく、CPU に共通の入口を登録する。現在の入口は、スタックが使える状態を前提にしている。元の処理へ復帰するためのレジスタ保存は実装していない。

```cpp
extern "C" void trap_handler() {
    uart_puts("Trap!\r\n");
    for (;;) {
    }
}
```

確認時は `kernel_main` の `Hello!` の直後に次を入れた。

```cpp
asm volatile("ebreak");
```

`ebreak` は今回の実行環境ではブレークポイント例外を起こす。`Hello!` の後に `Trap!` が出れば入口が動いたと分かる。このテスト命令は翌日取り除いた。

## 9. 原因の読み出しとインラインアセンブリ

```cpp
unsigned long cause;
asm volatile("csrr %0, mcause" : "=r"(cause));
```

**インラインアセンブリ**は、C++ の中にアセンブリ命令を書く方法。

- `csrr`：CSR を読む命令。
- 空白：命令名と引数を区切る。
- カンマ：出力先と読み取り元を区切る。
- `%0`：コンパイラが選ぶ出力先レジスタに置き換わる場所。
- `:`：アセンブリの文字列と、C++ 側の出力指定を区切る。
- `"=r"(cause)`：レジスタへ出力した値を、変数 `cause` に受け取る。

具体的な命令なら `csrr t0, mcause` と書けるが、**`%0` が必ず `t0` になるわけではない**。`%0` は0番レジスタという意味でもない。

今回の `ebreak` では `cause == 3` となり、ブレークポイント例外だと判定できた。

## 10. 数値を16進数の文字列にする

```cpp
void uart_put_hex(unsigned long value) {
    const char* digits = "0123456789abcdef";

    uart_puts("0x");

    for (int shift = 60; shift >= 0; shift -= 4) {
        uart_putc(digits[(value >> shift) & 0xf]);
    }
}
```

今回の `unsigned long` は64ビット。16進数の1桁は4ビットなので、16桁表示する。

1. `value >> shift` で表示したい桁を右端に移す。
2. `& 0xf` で右端の4ビットだけ取り出し、0〜15の値にする。
3. `digits[...]` で対応する `'0'`〜`'f'` を選ぶ。
4. 上の桁から1文字ずつ送る。

数値の `3` と文字の `'3'` は違う。数値 `3` を渡すと `0x03` が送られるが、数字を表示するには `'3'` の文字コード `0x33` を送る必要がある。`digits` はその変換表。

`mcause` と同様に `mepc` も読める。

```cpp
unsigned long epc;
asm volatile("csrr %0, mepc" : "=r"(epc));
```

`mcause` は「なぜ」、`mepc` は「どこで」を調べる手掛かり。実際の命令との照合は翌日のノートへ続く。
